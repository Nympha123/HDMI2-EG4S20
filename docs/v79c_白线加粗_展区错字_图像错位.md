## 2 底栏「青铜礼器展墓」→「青铜礼器展区」

**现象**：底栏右侧展区名最后一个字显示成「墓」。

**根因**：`subtitle_overlay.v` 里的 `zone_str9` 是**硬编码 9 bit 字形码**，而字形码是
`tools/make_subtitle_font.py` 按“字符首次出现顺序”分配的。`ZONE_PRE("展区")` 排在
字符表最后，所以「区」永远落在**最后一个新字**的槽位上：

| 版本 | ext 小字库新字数 | 「区」的码 |
|---|---|---|
| v79 / v79b 之前 | 63 | 0x13E |
| v79b（加了三行展区简介） | 117 | **0x174** |

v79b 扩容后 0x13E 这个槽变成了「墓」（简介第一行“曾侯乙**墓**出土”的第一个新字），
于是底栏就成了“展墓”。

**修法**：把 `zone_str9` 四个常量的最高 9 bit 从 0x13E 改成 0x174：

```verilog
2'd0: zone_str9 = 72'hBA44A0B0481C0A0220;  // 曾侯乙编钟展区
2'd1: zone_str9 = 72'hBA44A130883C184020;  // 青铜礼器展区
2'd2: zone_str9 = 72'hBA44A190B850804020;  // 唐三彩展区
default: zone_str9 = 72'hBA44A231087C3A1A20; // 越王勾践剑展区
```

并在 `make_subtitle_font.py` 里加了校验：只要「展」「区」的码不是 0x112 / 0x174 就打印
WARN，提醒同步改 `zone_str9`（防止下次改文案再踩）。

> 同一份 ext 字库里其它字（字幕、目录、简介）都是由工具重新生成的参数，码值自洽；
> 只有 `zone_str9` 是手写常量，所以只有它需要改。

## 3 图片整帧错位（每行被转 N 个像素）—— 概率性

**现象**：图片页偶尔整页内容横向错开（照片/文字从另一侧绕回来），概率不低；
顶栏/底栏这些 OSD 文字位置正常 —— 说明错的是**图像层**，不是合成层。

**根因**：`frame_read_write` 里的读 FIFO（`rfifo_32_32_512`）每帧在 vs 处要异步清零，
但原来的清零脉冲只有 `S_ACK && read_req_d2` 那几个 `mem_clk`（125 MHz，8 ns）——
折算到 `video_clk`（25 MHz，40 ns）只有 **1~2 个时钟沿**。而该 FIFO 的清零是
“异步置位 + 各时钟域两级同步释放”（内部 `asy_r_rst0/1` 按 clkr 采样）：

* 读时钟域只要**没踩到沿**，`rd_addr` 就不会回 0；
* 写指针回了 0、读指针没回 → 这一帧读出来的前 N 个字是上一帧留在环形缓冲里的旧数据，
  图像流整体错开 N 个像素；
* 因为图像按 640 逐行连续存放/读取，整体错开 N 个像素在屏上就是**每一行都被转了 N 个
  像素**（左右内容互相绕回）；
* N 取决于上一帧停在哪，所以表现为“概率性、时好时坏、一次错就一直错”。

**修法**（`rtl/SD/frame_fifo_read.v`）：

1. 清零脉冲固定拉宽到 **512 个 mem_clk（≈4 µs）**，远大于两个时钟域的同步需求，
   又远小于 1.4 ms 的场消隐；
2. 清零期间**禁止发起读突发**（`S_CHECK_FIFO` 增加 `aclr_hold == 0` 条件），
   否则清零窗口内的前几个突发会被吞掉，同样造成错位；
3. 复位/首帧行为不变（第一次 `read_req` 才清）。

代价：一个 9 bit 计数器 + 一个比较器（约 20 个 FF/LUT），不影响 BRAM/DSP。

## 4 资源与时序

| 项 | v79b | **v79c** |
|---|---|---|
| mslices / 4900 | 4535（92.54%） | **4537（92.60%）** |
| 综合 LUT / REG | 8654 / 6452 | **8683 / 6462** |
| BRAM / DSP | 59 / 20 | **59 / 20（不变）** |
| Setup WNS / TNS | +230 ps / 0 | **+1117 ps / 0（0 违例端点）** |
| Hold WNS / TNS | +25 ps / 0 | **+33 ps / 0（0 违例端点）** |
| place seed | 5 | **5** |

BRAM/DSP 没动。Setup 余量从 +230 ps 涨到 +1117 ps（网表微调后布局落点变好，
原先卡在 `sd_card_clk` 的 `source_done_seen→bmp_read` 长路径不再是最差路径）。

bit：`bitstream/HDMI2_HDMI14_Player_v79c.bit`（675,020 B，
