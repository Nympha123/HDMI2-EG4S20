# 滚动字幕与字库说明（博物馆版）

> 适用版本：2026-10-24 之后的 `HDMI2-EG4S20_New`。相关文件：
> `rtl/subtitle_overlay.v`（`info_bands` 模块）、`rtl/font_rom.v`、`rtl/font_rom_ext.v`、
> `rtl/font_rom.hex`、`rtl/font_rom_ext.hex`、`tools/make_subtitle_font.py`。

## 1. 现在的文案

字幕条（y = 424..439，底 `#CFE3F4`、字 `#25445C`）里 3 句循环，**第 1 句随展区变**：

| # | 文案 | 滚完一句 |
|---|---|---|
| 0 | `欢迎参观 · 礼乐重器曾侯乙编钟`（A 区）<br>`欢迎参观 · 青铜礼器`（B 区）<br>`欢迎参观 · 唐三彩`（C 区）<br>`欢迎参观 · 越王勾践剑`（D 区） | ≈15 s |
| 1 | `展厅内请保持安静，请勿触摸展品，拍照请关闭闪光灯` | ≈17 s |
| 2 | `开放时间 9:00—17:00，讲解服务请至前台预约` | ≈18 s |

- 速度 1 像素/帧（60 Hz ≈ 60 px/s），整轮 ≈ 50 s。
- **换展区会重置到第 1 句**（`zone_sel` 变化即 `scroll_pos=0、sub_idx=0`），
  所以从目录进任何一个区，第一眼看到的都是该区的欢迎语。
- 字幕只占图片层之上的一层，不影响下面的图像/波形；目录页、主菜单、设置面板会盖住它。

## 2. 编码与字库（为什么有第二片 ROM）

- 字符码 **9 bit**：`0x000..0x0FF` 用主字库 `font_rom`（4096 深 = 256 槽 × 16 行，8 块 BRAM）；
  `0x100..0x1FF` 用字幕专用 `font_rom_ext`（1024 深 = 64 槽 × 16 行，2 块 BRAM）。
- 主字库的 256 个 8 bit 槽位**已经被历史文案占满**（ASCII 0x20–0x7E、0x80–0xAF 的 48 个汉字、
  0xB0–0xFF 的 96 个汉字）。所以新字必须用 9 bit 码。
- 如果让主字库也吃 9 bit 码，它会被推断成 8192 深：单实例 8 → 15 块 BRAM，
  整个设计 BRAM 会从 **55 涨到 62 / 64**（只剩 2 块，没有余量）。
  现在的做法是"主字库地址固定 12 bit + 另开 1024 深小 ROM"，实测只 **+2 块**（55 → 57 / 64）。
- 两片 ROM 并行读、同一拍寄存地址、同一拍输出，用 2 拍延迟的 `ext_d` 选输出，
  所以像素侧时序还是原来的 2 拍，字形不会错位。
- 字幕里出现的已有字（欢迎参观 · 请 展 切 换 画 面 …，都是当年 msyh 渲染的老字模）
  直接复用老槽位，只有确实缺的 **51 个字**才进 ext ROM（`tools/subtitle_glyph_map.txt` 有完整映射）。

## 3. 资源代价（实测，TD 6.2.168116，EG4S20BG256）

| 项 | 改前 | 改后 | 变化 |
|---|---|---|---|
| BRAM9K | 55 / 64 | **57 / 64（89.1%）** | +2 |
| LUT 单元 | 15047 / 19600 | 15135 / 19600 | +88 |
| 寄存器 | 6087 | 6090 | +3 |
| DSP | 22 / 29 | 22 / 29 | 0 |
| **mslices** | 4197 / 4900 | **4209 / 4900（85.9%）** | **+12** |
| Setup WNS（布线后） | +1073 ps | +1148 ps | +75 ps |
| Hold WNS（布线后） | +7 ps | +3 ps | −4 ps（布局差异，非本次改动引入） |

> 对照：不做 ext ROM、直接让主字库吃 9 bit 码的方案实测 **BRAM 62 / 64**（96.9%），已无余量，故不采用。
> 结论：这次改文案对 mslices 几乎无影响（+12，约 0.25%），代价集中在 2 块 BRAM；
> 器件余量仍为 **mslices 691 块（14.1%）、BRAM 7 块、DSP 7 个**。

## 4. 怎么改文案

1. 编辑 `tools/make_subtitle_font.py` 顶部的 `SENTENCES`：
   `(名字, 文案, 字数)`，每句 ≤ 32 字；第 1 组是随展区的欢迎语（A/B/C/D 四个），其余是通用句。
2. 运行 `python tools/make_subtitle_font.py`：
   - 重写 `rtl/font_rom_ext.hex`（1024 行）
   - 重写 `tools/subtitle_params.vh`（可直接贴的 localparam）
   - 重写 `tools/subtitle_glyph_map.txt`（字 → 码）
   - 预览存到 `tools/_subtitle_preview.png`（可用环境变量 `SUBTITLE_PREVIEW` 指定路径）
3. 把 `tools/subtitle_params.vh` 里 `localparam [287:0] SUB_*` 六行（4 个展区欢迎语 + 2 句通用）
   贴进 `rtl/subtitle_overlay.v` 的同名位置，并同步：
   - `sub_idx` 的 `case` 分支与 `sub_len_r` 的字数；
   - 滚动结束时的回绕值 `(sub_idx == 2'dN)`。
4. 字模改了以后，**综合时 `font_rom_ext.hex` 必须能被 `$readmemh` 找到**（与 `font_rom.hex` 同规则：
   放在 TD 工程目录下；本工程实测是"工程目录"，不是 run 目录）。

## 5. 限制与余量

- ext ROM 只有 **64 个槽**（1024 行 / 16）。当前用 51 个，还能再加 13 个字。
  超过 64 个要把 `font_rom_ext.v` 扩成 2048 深（+2 块 BRAM）或回收主字库里的废弃槽位。
- 每句最多 32 字（向量 288 bit、`sci_c` 5 bit）。
- 标点请用 `，`(0xA6)、`·`(0xB4)、`：`(0xBA) 这些已有槽位：
  新渲染的标点会被 16×16 包围盒"居中"，逗号会飘到半腰，不要重新生成。
- 主字库 `font_rom.hex` 这次**一个字节都没改**，其他 OSD（主菜单、设置面板、顶栏、底栏）完全不受影响。
