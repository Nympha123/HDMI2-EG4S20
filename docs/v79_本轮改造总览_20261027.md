## 2 三个现场故障的根因（v79）

| 现象 | 根因 | 修法 |
|---|---|---|
| 主界面按 Q 跳到别的界面 | `menu_ctrl.v` 主菜单分支里 `else if (back_ev) menu_active <= 1'b0;` 把菜单关掉了 | 删掉该分支，主界面 Q 无效 |
| 展区 1 逛完回主界面，音乐**永久静音** | 换曲时 `aud_state` 把 `wav_sector_req` 从播放器切给查找器，而播放器可能正在 `WS_FILL` 等自己那笔 `sd_done`：两边共用一组 `sd_valid/sd_done`，互相吞；最致命的是播放器进了 `WS_FILL` 但 `sd_req` 已被 mux 掉，仲裁再也不会为它开事务 → 永远等不到 done，`ended` 不置 1，也不会再 restart | 换曲**串行化**：拉低 `play_enable` → 等 `player_idle` → 才 `start` 查找 → 查到后 `restart` + 新 LBA + 开播；播放器加 84 ms 事务看门狗；`restart` 跨 50→25 MHz 拉宽到 16 拍再 2FF 同步 |
| 进别的展区仍停在“曾侯乙” | `sd_card_cmd.S_READ_WAIT` 等数据令牌 0xFE **没有超时**，卡漏应答就永久卡死，`sector_busy` 恒 1；`owner_wav` 还可能被锁死把图片数据永久屏蔽 | 令牌等 84 ms 超时→`S_ERR`；`sd_sec_read_error` 如实上报（原来 `sector_error` 恒接 0）；两个 FAT 扫描器各加看门狗；顶层再加“总线连续 336 ms 不收尾就复位整个 SD 子系统”的兜底 |

## 3 界面迭代（v79b / v79c）

- **白色竖线**：最终决定“把消不掉的白边做成设计的一部分”——左右各 4 px 纯白。
  左边那条本来就是 OSD 比 DE 晚 D 拍的残影，显式涂白后颜色固定；右边涂白后，下一行行首的
  残影会把白线“印”回左侧，天然对称。目录页不加（`~dir_active`）。
- **目录页简介**：左下角补三行（每区 3 行），底栏提示“请勿触摸展品”挪到最底部。
  为此 ext 字库 64→128 槽，并把原本“字幕一份 + 目录一份”的两片 ROM 合并成顶层一片共用，
  BRAM 总数不变。
- **「展墓」错字**：`zone_str9` 是手写 9 bit 字形码，而码值是工具按“字符首次出现顺序”分配的；
  `ZONE_PRE("展区")` 在字符表最后，新字数量一变，「区」的码就从 0x13E 漂到 0x174。
  修法：常量改成 0x174，并给生成脚本加了码值校验（不符就 WARN）。
- **整帧错位（每行被转 N 像素）**：读 FIFO `rfifo_32_32_512` 的异步清零只在
  `S_ACK && read_req_d2` 几个 `mem_clk` 内有效，折算到 25 MHz 读时钟只有 1~2 个沿，
  **读指针常常没被复位** → 帧相位随机 → 整帧错开 N 个像素（按 640 行连续存放，看起来就是
  每行旋转）。修法：清零固定拉宽到 512 个 `mem_clk`（4 µs），且清零期间禁止起读突发。

## 4 音频专题（v79d）

**为什么变差**：v79 为省资源把 WAV 环形缓冲 1024→512，并把读侧策略从
“攒满一个扇区（256 样本）才放”改成“有数就放”。水位从 ~760 掉到 ~248，抗抢占余量只剩 5 ms，
每次起播/换曲都经历欠载 → 样本流被截断/插静音，听感就是“滋滋”变重。

**处理**：整体回到 v60——缓冲 1024 样本（21.3 ms）+ `level_rd >= 256` 才起播、
`WS_END/WS_WAIT` 收尾阶段允许放余量；v79 的换曲握手/看门狗/restart 跨域等安全性保留；
音量、增益、ACR、采样节拍未动。

**顺带把缓冲搬进 BRAM**：原来读、写都写在带大量无关逻辑的大 `always` 里，TD 推不出 BRAM，
1024×16 被铺成 LUTRAM（近 1000 LUT）。改成标准双端口写法后正常推断：

```verilog
always @(posedge wr_clk) if (buf_we) buffer[buf_waddr] <= buf_din;  // 写地址要单独锁一拍
always @(posedge rd_clk) buf_q <= buffer[rd_ptr];                   // 读地址/输出各自寄存
```

代价 2 块 BRAM，省 546 LUT。

> 遗留结论（与前两份 docx 一致）：**“滋滋”与 SD/WAV 数据链无关**（v70t 内部 1 kHz 正弦同样有），
> 下一步只能做 I2S 回环实验位，或用 HDMI 音频分离器抓数字流。

## 6 可复用的经验（本轮踩出来的）

1. **异步 FIFO 的清零必须横跨两个时钟域**：清零脉冲至少要覆盖慢时钟域 2~3 个沿
   （本工程 25 MHz ≈ 120 ns），否则读/写指针相位会随机错开，表现为“整帧错位/每行旋转”，
   而且会一直保持到下次碰巧清上——看起来就是“概率性、复现不低”。
2. **手写的字形码常量是脆弱点**：字库槽位一扩，末尾字符的码就会漂。凡是手写 9 bit 码的地方
   （`zone_str9`）必须有工具校验。
3. **双时钟 RAM 想推 BRAM，要拆成标准双端口模式**：写口单独 `always` + 写地址单独寄存，
   读口单独 `always` + 输出寄存；读写在同一个带无关逻辑的大块里，TD 只会铺 LUTRAM。
4. **常量开关要配合状态跳转才能裁死代码**：`hdr_any_size=0` 时如果状态机仍经过 `ST_PADTOP`，
   那段减法循环照样进网表；把跳转写成 `state <= hdr_any_size ? ST_PADTOP : ST_LOAD_DATA`
   才能真正裁掉。
5. **place seed 不是随便换的**：同网表 seed 3/5 可用（+241/+488 ps），**seed 4 出负 slack**
   （−6 ps、4 个违例端点）。重编后必须看 `route_flow.status` 的 `NUM_FEPS=0`。
6. **白边只能“共存”**：三次回填（v70/v73/v75）都证明在输出级补像素无法既不串色又不留线；
   最终方案是把它做成对称装饰线，且左侧覆盖保证以后真修了 DE 时序也不变样。
