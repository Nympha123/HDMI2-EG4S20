# lab_ex4_tf — TF 卡 BMP 轮播 + HDMI 1.4b 视频显示

本目录为 **APUG092_HDMI1.4b_Transmitter_V1.4** 工程的纯视频播放版本，专注于 TF 卡读取、HDMI 视频输出及可靠性提升。

完整版《设计参考例程》文档见 **[设计参考例程文档.md](设计参考例程文档.md)** / **[设计参考例程文档.docx](设计参考例程文档.docx)**。

## 1. 工程功能简介

本工程实现了一个基于安路 FPGA 的多媒体播放系统，主要功能与特点如下：

1. 从 TF 卡中读取 BMP 图片；
2. 支持最多四张图片（`PIC1.BMP`~`PIC4.BMP`）的上电扫描与**四 bank 预加载**：四张图分别装入 SDRAM 的 4 个 bank，切换时只切 bank 索引、**不再读卡**，因此切换无黑屏、无撕裂、无卡顿；
3. 通过开发板的 HDMI_B 接口在显示器上显示图片；
4. 支持 **key1** 手动切换下一张图片；
5. 支持 **key2** 短按开启/关闭自动轮播（约 3 秒一张），**key2 长按约 1 秒切换到上一张**；
6. 具备完善的**上电防抖复位（POR）机制**：三个 PLL 全部锁定且同步后才释放复位，防止上电时钟抖动导致花屏或死机；
7. 具备**SD 卡读取防死锁机制**：图片头部非法、文件长度/像素不足、读取无进展（**500 ms 内没有任何扇区或字节进展**）都会被判定为错误并上报；失败图片按"重试 1 次 → 屏蔽该图 → 装载下一个可用槽位"处理，期间保留上一帧完整画面，不会卡死；
8. **快速启动**（`fast_boot_gate`）：首张图装载完成即可显示，其余图片在后台继续预加载。

> **架构（第八讲：四 bank 帧缓存）**
> ```
> TF/FAT32 → sd_card_bmp（扫描+校验+BMP解析，sd_card_clk）
>              │ pixel_valid / pixel_rgb / frame_commit / decode_error
>              ▼
>      media_frame_loader ──► media_sdram_write_cdc ──► SDRAM（4 bank，加密 IP 不变）
>                                                        │ Sdr_rd_en/Sdr_rd_dout
>                                                        ▼
>      video_timing_ctrl ──► media_frame_reader ──► rgb_video_adapter ──► HDMI 1.4b 核
>      media_player_control（按键/轮播 → active_index）
> ```
> 原 `frame_read_write` + `video_timing_data` + `video_delay` 桥接层已被上述模块取代；SDRAM 控制器与 HDMI 发射核逐字节未改。详见 `doc/第八讲移植方案.md`。

> **前七讲定版（历史基线）**
> - bitstream：`doc/前七讲定版/HDMI1.4b_Transmitter_v1.0_L1-L7_85ED31EB.bit`，MD5 `85ED31EBC32AD6D2BF9EFED33D4FCC2F`
> - 冻结文件清单（含全部源码 MD5）：`doc/前七讲定版/MANIFEST_MD5.txt`
> - 定版说明与已知限制：`doc/前七讲定版/定版说明.md`

## 2. TF 卡图片格式要求

TF 卡中的图片必须满足以下要求：

```text
图片格式：BMP
分辨率：640 × 480
颜色格式：24-bit RGB
压缩方式：非压缩
文件名  ：PIC1.BMP / PIC2.BMP / PIC3.BMP / PIC4.BMP（8.3 大写，放在根目录）
```

注意事项：

1. 不能直接把 PNG、JPG 改后缀为 `.bmp`；
2. 必须使用真正的 BMP 文件；
3. 建议 TF 卡格式化为 FAT32；
4. **当前固件按文件名匹配**：只认根目录下的 `PIC1.BMP`~`PIC4.BMP`（8.3 短文件名，属性为普通文件）。**文件名大小写不敏感**（`PIC1.bmp` 也能识别）；但落成长文件名条目（如 `PIC1~1.BMP`）或放在子目录里则会找不到。
5. **数码管状态读数表**：

```text
0 = 尚无任何 bank 装载完成（SD 未初始化 / 正在扫描）  1~4 = 正在显示 PIC1~PIC4
9 = 图片头结构非法（ERR_HEADER）      A = 读取超时（ERR_TIMEOUT）
B = 文件长度/像素不足（ERR_TRUNCATED） C = 根目录没有 PIC1~4.BMP
D = 卷/BPB 不认识（不是 FAT32 或分区表异常）  E = SD 扇区读取失败
```

> 第八讲起，数码管显示"**当前正在显示的 PIC 序号**"（取自 `media_frame_reader.reader_index`），
> 而不是"最后装载的图片"；一旦出现错误码（≥9），错误码优先显示。
6. **推荐使用本工程提供的 Python 辅助脚本来处理图片**：`doc/convert/sync_to_sd.py` 已改为把图片按顺序命名为 `PIC1.BMP`~`PIC4.BMP`，并**不再破坏旧 BMP 的文件头**（那是裸扇区扫描时代的做法）。

### Python 辅助脚本 (位于 `doc/convert` 目录)
我们在 `convert` 文件夹中提供了两个极其方便的辅助脚本，免去了手工调整图片和解决 FPGA 物理扇区缓存残留的问题：
- **`convert_images_to_bmp.py`**：一键将任何常见的格式（JPG、PNG、WebP 等）批量转换为严格符合 FPGA 要求的 `640x480 24位无压缩 BMP` 格式。
- **`sync_to_sd.py`**：SD 卡一键安全同步工具。由于直接在电脑上删除旧图片往往**无效**（旧图片的物理数据会残留在底层扇区中导致 FPGA 读取出错），该脚本会自动破坏 SD 卡中所有旧图片的文件头、清空数据并写入新图片，彻底防止死锁和读到旧图。详细使用请参考 `convert/README.md`。

## 3. 硬件连接要求

开发板上有两个 HDMI 接口，本工程需要使用：

```text
HDMI_B
```

连接方式如下：

```text
开发板 HDMI_B → HDMI 线 → 显示器
```

注意事项：

1. HDMI 线必须插在开发板的 `HDMI_B` 接口上；
2. 图像通过 `HDMI_B` 接口完成输出。

## 7. 最简复现说明

只需要确认以下三点：

```text
工程文件：
src/td_project/HDMI1.4b_Transmitter_v1.0.al

代码文件：
src/user_source/hdl_source
src/user_source/ip_source
src/user_source/constraints_source

示例图片：
doc/TF卡图片
```

然后将 `doc/TF卡图片` 中的 BMP 图片按第 2 节重命名为 `PIC1.BMP`~`PIC4.BMP` 复制到 TF 卡（或者使用 `convert` 脚本工具生成），将 HDMI 线插入开发板的 `HDMI_B` 接口并连接显示器，打开工程并下载到 FPGA，即可复现 HDMI 图片轮播功能。
