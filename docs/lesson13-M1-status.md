## 一、第一阶段「省 LUT 的色度通路」——已按用户决定「甲」关闭

**目标是**：把亮度 + 对比度两级（每通道各 2 个 8×8 乘法器，共 **6 个**）合并为共享的一级 `x*K1+K2`（每通道 1 乘法 + 1 加法 + 饱和），期望 LUT 下降。

**实际做法与实测**（提交 `5a76d7b`，已回退）：

| 项 | 实测值 |
|---|---|
| 新增模块 | `colour_fade_adjust.v`（`out = sat((x*K1)>>>15 + K2)`，组合输出，保持 RGB 与 DE 同拍） |
| 系数 | `K1 = (B*C*(A+1))>>8`（Q15，默认 B=192/C=128/A=255 时 = 24576 → **与旧路径逐位相同**）、`K2 = 128-C` |
| LUT | **8243 → 8239（−4，等于无收益）** |
| 寄存器 | **+24（7036）** |
| 时序 | Setup **+417 ps → +168 ps**（余量变小） |
| 结论 | **无收益，已回退**；`colour_fade_adjust.v` 保留在工程里但**未例化**（零逻辑影响） |

**为什么省不下来（根因，已量化）**：EG4S20 **没有 DSP**，乘法器全部用 LUT 实现。合并后每通道从"2 个 8×8"变成"1 个 8×16"，**乘法器个数减半但每个的 LUT 成本约翻倍**，总数基本不变。同理，方案 A（把亮度折进原转场 alpha）与方案 B（原地合并）也会得到相同结果。

**因此**：在不减少功能的前提下，本工程的色度通路**没有可省的 LUT**。要真省只能砍功能（例如转场不做整帧淡出），属产品取舍，本次不做。

### 2.2 关键架构发现（与教案假设不同，已核实）

教案 §4.2 假设「`media_frame_reader` 按坐标读 SDRAM（第 7 课已建）」。**我们树里的 reader 不是这样**：

```
media_frame_reader 端口（实测）：mem_clk / controller_* / refresh_active / writer_active /
app_rd_en / app_rd_addr / sdram_rd_valid / sdram_rd_data /
pix_clk / frame_start / active_index[1:0] / pixel_consume /
pixel_rgb / pixel_valid / underflow / reader_busy / rd_burst_active /
frame_read_done / reader_index / reader_error
```

即：**给一个 bank 号，就顺序整帧流式读出**（`BURST_SIZE=128`、`MAX_INFLIGHT_BURSTS=2`、`FIFO_DEPTH=512`），**没有坐标输入**。
→ 所以 2×2 缩略图屏必须让读通路具备「按 (bank,x,y) 点读」的能力。

**存储格式（实测）**：`IMAGE_WORDS = 307200`（= 640×480）、`bank_base(b) = IMAGE_WORDS*b`、`pixel_rgb = prefetch_data[23:0]`
→ **一个字 = 一个像素**，地址 = `bank*307200 + y*640 + x`。

**带宽预算（实测推算）**：缩略图屏每帧只需 **76,800** 次唯一源像素读（4 张 × 160×120；×4 放大时相邻 4×4 显示像素共用同一源像素），60 fps 下 **≈4.6 M 次/秒**，**远低于**现有全屏路径的 18.4 M/秒 → **最近邻完全够用**；教案警告的带宽问题只针对双线性（每像素 4 读）。
