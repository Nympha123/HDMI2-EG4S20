# v45 底部两条带等高 + 删除进度条

日期：2026-10-26

## 1. 改动

根据板测截图，底部区域原来分成：

```
字幕带   416..455   40 px
底栏     456..479   24 px
```

两条带高度不一致，且底栏左侧有一根 130 px 的旧进度条（`BAR_X0..BAR_X1` =
110..240，`BAR_Y0..BAR_Y1` = 465..471），在现场看就是"左下角一条奇怪的横线"。

v45 改为：

```
字幕带   416..447   32 px
底栏     448..479   32 px
```

- 总高度仍然是 **64 px（40+24 = 32+32）**，图片区（32..415）和顶栏（0..31）完全不动；
- 字幕文字仍在 424..439，正好在 32 px 带内居中；
- 底栏文字从 460 上移到 **456..471**，在 32 px 带内居中；
- 删除旧进度条：`C_TRACK`、`BAR_X0/X1/Y0/Y1`、`bar_fill`、`bar_end`、`on_bar` 全部移除；
- 底栏只保留 `n / m`（左，x=8）和展区名（右，右对齐到 x=632）。

字幕带顶部 1 px 金色强调线（`SUB_Y=416`）和底栏上沿 1 px 分隔线
（`BOT_Y-1=447`）保留。

## 3. A05/A06 加载速度分析

当前 SD 读是 **SPI 12.5 MHz + 每 512 B 一个 CMD17**。A05（1280×960，N=2）
要读 480 行 × 8 扇区 = **3840 个扇区**；A06（1920×1440，N=3）要读
480 行 × 12 扇区 = **5760 个扇区**。每扇区卡内延迟约 1–3 ms，远大于
512 B 的传输时间，所以体感是 3.9 s / 5.8 s 左右。

可选提速手段（按性价比）：

1. **CMD18 多块连续读**（推荐，但需要改 SD 核）：
   一行 8/12 个扇区只发一次命令，读完再用 CMD12 停止。预计 A05/A06
   从 3.9/5.8 s 降到 **1.2/1.8 s 左右**（约 3×），代价是一个块计数器 +
   读状态扩展 + CMD12 收尾，约 100–200 LUT，不一定要加 BRAM。
2. **后台预装下一张**：4 个 SDRAM bank，显示当前图时把下一张读进空闲 bank。
   切换可做到"秒开"，但会与 WAV/自动轮播抢 SD，工程以前做过预载并因
   自动跳页/方向错乱回滚过，需单独验证。
3. **降源图分辨率**：把 A06 从 1920×1440 降到 1280×960（或 A05/A06 都
   改成 640×480），加载立刻变快，但 3× 缩放演示就没有了。
4. **提高 SPI 时钟**：12.5→25 MHz 只能省掉传输时间（约 15–20%），
   因为卡内延迟才是大头；还要改 `spi_master`/时钟，收益不如 CMD18。

v45 先不改 SD 读链路，避免把已经稳定的读图/音频仲裁改坏；建议把
CMD18 作为单独的 v46 做，先在 A05/A06 上验证，再推广到全部图。
